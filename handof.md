LOOKS WRONG BUT IS DELIBERATE - don't undo without asking
- max_tokens: a client sending 0 used to become 9024. A hop's "maxTokens" is a FLOOR (glm-5.3-nv = 32000) because GLM-5.3 spends max_tokens on thinking AND the reply.
- A stream that dies without finish_reason gets finish_reason "length" + [DONE] (+ a visible notice if there was no reply text). Not a pass-through on purpose.
- TPM: only providers listed in provider-limits.json "tpmCountsInputOnly" (["google"], confirmed) count input tokens only; every other provider stays conservative (input + max_tokens) because how they count is unknown. `tpmLimit` is a per-REQUEST input-size cap, `tpm` is the per-minute budget (fixed clock-minute window). Never add max_tokens to Google's TPM again: a ~9.5K prompt + the 9024 fallback once skipped the hop as "18.5K > 14K".
- provider-limits.json is loaded at the TOP of server.js, above every function that reads it (a `typeof` guard on a const there protected nothing). It is also re-read after the boot-time GitHub pull.
- "Unlimited" means "retry the same hop up to 100 times". It applies to every nvidia hop, limitType "unlimited", retryAsUnlimited, and Literouter hops with NO dailyCap (so adding a dailyCap turns that into a single try). Retry window starts at the FIRST failure: 45s with a fallback, 10 min on the last hop, and is only checked BETWEEN attempts - a running attempt is never cut, so "after 3 attempts over 15m 7s" with a 10m window is normal (the error explains it). Decided: keep it provider/flag-based.
- Errors that can't fix themselves are NOT retried: AUTH (also a 500 whose body says invalid key), BAD_REQUEST, CONTEXT_TOO_LONG, QUOTA. NOT_FOUND (404) and NET_CONFIG (bad URL/TLS) stop retrying but still fall to the next hop. DNS failure = 3 tries. Assumption: a 404 is permanent - if NIM answers 404 while warming up, remove NOT_FOUND from NO_RETRY_BUT_FALL_BACK_TAGS.
- QUOTA outranks 429 in classifyError (patterns match any status; broad words like billing, daily limit, resource_exhausted). A quota-worded 429 stops retrying, still falls back, and is returned as 429. Google's own 429s land here too.
- Client hang-up aborts the in-flight upstream call (AbortController), even while queued at the provider. Removing it brings back ghost generations that ran to the end for nobody (seen: 3m52s on GLM-5.3) and competed with the retry.
- Errors are short and logged once: a terminal failure is only in the request-level ERROR line (no WARN+ERROR pair); a single-hop model never mentions hops/chains/attempts and its error has no `attempts` array; multi-hop chains keep `attempts` + X-QProxy-Fallback-Path. Google "models/" prefixes are hidden in labels only - the wire name stays as stored.
- sync-add strips "models/" from Google ids and model names (it used to create "models-gemini-...-g" duplicates) and pre-fills limits from provider-limits.json. Google slugs in that file are derived by naming convention.
- Request ids (#k3f9) come from shadowing `const log = logWith(rid)` in the route and makeAPICall (AsyncLocalStorage deliberately not used). THINK/REPLY blocks are stamped with when they STARTED. PROMPT entries are Admin-only. Admin log holds 1000 entries.
- Admin lockout is per IP and checked BEFORE the key (5 wrong keys -> 30s, doubling to 1h). The page stops polling on 401/429 so a stale tab can't extend its own lockout. ADMIN_KEY is optional at boot: unset = every /admin request 503s and a WARN says so.
- Sync groups: Literouter Free / Premium Basic (+ collapsed "other"); OpenRouter Free (open) + Paid (collapsed; free = price 0 or :free, NOT split by price - I asked for just free or paid); Google Free·generous (>= GOOGLE_GENEROUS_RPD = 500/day) + Free·thin ice open, Paid only (0/0/0) + Not in the saved table collapsed; Z.ai Free (list baked into provider-limits.json from Z.ai's official pricing page) + Paid. NVIDIA NIM has NO grouping on purpose: the hosted endpoint is free-only (paid = self-hosting with an AI Enterprise licence; from NVIDIA's FAQ via search, not verified live).
- Hop warnings (gone / turned-paid / limits-changed) come from three sources: the provider's live /models (when a Sync panel opens, every 6h, and "Check now"), a real request that got "model does not exist" (cleared by the next success), and the saved tables in provider-limits.json. They never switch a hop off. A catalog "gone" outranks a saved-table warning. `ignoreCatalog: true` on a hop silences the list check for a model that works but is hidden (kimi-k3 on NIM). An EMPTY live list is ignored on purpose. "limits changed" marks only the hop that differs. QP_NO_CATALOG_WATCH disables the 6h timer (tests only).
- Literouter FREE models have a fixed 5,000-token context (provider-limits.json literouter.freeContextTokens); longer prompts are summarized by Literouter, not rejected. The proxy only LOGS this ([context] WARN, once per hop attempt, estimate = chars/4); it does not block. tpmLimit on a hop is the opt-in way to skip such a hop for long chats.
- NOT_FOUND is also recognised from the BODY on 400/410/422 ("model ... does not exist", unknown model, model_not_found): providers disagree on the status code. A dot inside an id (glm-4.6) is allowed, a sentence end is not; "invalid model" only counts when followed by id/name or a colon/quote ("Invalid model parameter ..." is a bad field, pinned by a test); "temporarily unavailable", "tool not found" and "does not support tools" are deliberately NOT gone (pinned by tests).
- models.json: gemini-flash-g sends gemini-3-flash-preview (Google's docs list only that id; the bare one was probably wrong). gemini-3.1-flash-lite-preview (the 500/day primary) and gemini-2.5-flash are left alone: the catalog check flags them if Google's live list drops them (one third-party source says the 2.5 models shut down 16-10-2026; unconfirmed).
- Resets are baked in, no env vars: Literouter 00:00 GMT+7 (17:00 UTC), OpenRouter 00:00 UTC, Google midnight Pacific (DST-aware).
